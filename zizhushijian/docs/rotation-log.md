# 轮值协调记录

轮值场次：第 6 周课堂实践 · 本组第 2 次轮值
协调人（轮值）：本人
参与人：第 4 组全体 5 名同学（线下 + 共享文档异步补充）

## 议题一：期末原型选题与模块划分

- **背景**：每人需完成含页面/样式/交互/数据（三维为进阶）的技术整合原型。
- **讨论**：A 同学建议统一做校园看板方便互评；本人提出做个人主题站
  （TRIGUN 介绍）以延续个人风格；B 同学担心个人题材的「数据」模块没真实数据。
- **分歧**：统一模板 vs 个人主题。担心点集中在数据真实性与互评可比性。
- **结论**：不强制统一主题，但四模块划分与质量清单按同一模板自查；
  数据允许模拟，但必须在页面与 README 标注来源（此条后来写入本人 README）。
  本人按此结论推进 TRIGUN 主题。

## 议题二：三维模块的技术选型与文件位置

- **讨论**：Three.js 与 A-Frame 二选一；三维场景放独立 html 还是单页内嵌。
- **分歧**：C 同学主张 A-Frame（写标记语言上手快）；本人主张 Three.js
  （沿用课堂七代码模式，自由度高）；D 同学提醒多页面会拉长导航维护成本。
- **结论**：允许自选，本人选 Three.js；三维区独立 `three-d/scene.html`
  但导航栏代码与全站保持一致，返回用页面内「返回首页」按钮，兼顾隔离与统一。

## 议题三：互评（同伴审查）的时间与形式

- **讨论**：随堂口头互评 vs 课后书面记录。
- **结论**：采用「随堂口头提意见 + 24h 内书面归档」，
  每条意见必须标注采纳/拒绝/修改及理由，模板统一放在
  `docs/peer-review.md`（本组约定文件名）。

## 轮值小结

本次轮值形成 3 项组内共识，均已在本人项目中落实；
会后将本记录与自查模板分享到小组共享文档。
